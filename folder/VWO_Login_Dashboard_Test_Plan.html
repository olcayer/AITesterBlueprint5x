04 ? Test strategy

Use risk-based testing, prioritizing authentication bypass, account isolation, token misuse, recovery and session failures. Apply equivalence partitioning and boundary analysis to inputs; decision tables to account states ? credentials ? MFA/SSO policies; state transitions to session and reset-token lifecycles; end-to-end use cases to new and returning users. Add exploratory sessions for interrupted workflows and usability.

Each candidate build first runs smoke coverage: page available, valid login, invalid login, reset request, protected-route denial and logout. Reject a build with a failed critical smoke check. Run targeted feature tests and API integration checks on stable builds, retest fixes, then run impacted and full release regression. Combine real sandbox integrations with deterministic fault-injection tests.

Proposed automation: Playwright with TypeScript, page objects, role/label selectors, isolated accounts and explicit assertions. Wait on observable state rather than fixed sleeps; control test clocks where supported for expiry checks; use independent data and clean up sessions. Capture traces on failure and investigate flaky tests rather than masking failures with retries. Keep exploratory, assistive-technology and security review work manual where appropriate.

07 ? Defect reporting procedure

Record defects in the agreed tracker (Jira proposed): summary, linked requirement/scenario, build and environment, synthetic-account state, reproducible steps, expected/actual results, timestamp/timezone, frequency and redacted screenshots, traces or logs. Never attach live secrets. QA Lead triages daily with engineering; security-sensitive issues use restricted access and immediate escalation.

SeverityExamples / handling
S1 ? criticalAuthentication bypass, cross-tenant access, credential exposure or widespread inability to log in. Notify Security/engineering immediately; block release.
S2 ? highCore reset/MFA/SSO failure, session invalidation failure, or major supported-user access barrier. Block release pending fix and verification.
S3 ? mediumRecoverable workflow or usability issue with a workaround. Prioritize by impact; unresolved items need explicit acceptance.
S4 ? lowMinor cosmetic/documentation issue without material workflow impact. Schedule and record disposition.

Workflow: New ? Triaged ? Assigned ? In progress ? Fixed ? QA retest ? Closed, or Reopened. QA verifies the original reproduction plus related regression. Priority is assigned separately from severity. Daily reporting includes planned/executed/passed/failed/blocked counts, requirement coverage, defect age, reopen rate and release risks.
